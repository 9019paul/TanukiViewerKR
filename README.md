# Tanuki Viewer KR

로컬의 **타누키 스타터 키트**를 브라우저에서 탐색하는 Windows용 로컬 뷰어입니다. 스타터 키트 이미지 자체는 이 저장소에 포함하지 않습니다.

## 실행

1. 최초 배포 ZIP을 한 번만 압축 해제합니다.
2. `START_Tanuki_Viewer.bat`를 실행합니다.
3. 브라우저에서 **스타터 키트 열기**를 눌러 로컬 폴더를 선택합니다.

`index.html` 직접 실행도 가능하지만 GitHub 자동 업데이트는 로컬 런처를 통해 실행했을 때만 동작합니다.

> 현재 이 저장소의 주 목적은 **자동 업데이트 채널 + 패치 저장소**입니다. 최초 설치는 완전한 배포 ZIP으로 진행해야 하며, 저장소의 Download ZIP을 설치본 대신 사용하지 마세요.

## 업데이트 방식

Viewer는 `main` 브랜치의 `update-manifest.json`을 확인합니다. 원격 버전이 더 높으면 manifest에 기록된 파일 중 **로컬 SHA-256이 다른 파일만** 다운로드합니다.

다운로드 파일은 임시 폴더에서 SHA-256 검증을 통과한 뒤 교체되고, 실패하면 기존 파일을 복원합니다. 스타터 키트 원본 GIF/PNG/WebP와 사용자 표시명(localStorage)은 업데이트 대상이 아닙니다.

업데이트 완료 후 화면의 버튼이 **새로고침해 적용**으로 바뀌며, 새로고침하면 새 코드가 적용됩니다.

## 누적 업데이트 목록

`config/update-files.txt`에는 v0.6.0 기준 설치본 이후 변경된 프로그램 파일을 누적해서 기록합니다.

예를 들어:

- v0.6.1에서 `js/app.js` 변경
- v0.6.2에서 `css/style.css` 변경

이라면 v0.6.2 manifest에는 두 파일을 모두 유지합니다. 사용자가 v0.6.0에서 바로 v0.6.2로 넘어가도 두 파일을 모두 검사하며, 이미 최신 해시인 파일은 다시 다운로드하지 않습니다.

새로운 전체 기준 설치본을 배포할 때만 이 누적 목록을 초기화합니다.

## 새 버전 배포

1. 변경 파일을 이 저장소의 동일 경로에 업로드합니다.
2. `VERSION.json`의 버전을 올립니다.
3. 변경된 파일 경로를 `config/update-files.txt`에 추가합니다. 기존 항목은 유지합니다.
4. `tools/Build-Manifest.ps1`로 manifest를 재생성합니다.
5. `update-manifest.json`까지 `main`에 반영합니다.

기존 이용자는 Viewer의 업데이트 버튼만 누르면 됩니다.
